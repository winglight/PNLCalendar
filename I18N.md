# Native Chinese / English interface

The header, Settings, and open form dialogs include language controls. The chosen
language is stored as `pnlCalendarLocale` in this browser only. Without a saved
choice, the interface follows Chinese/English browser language; unsupported or
unreadable settings fall back to Simplified Chinese. No translation service or
additional dependency is used.

## State and compatibility

- `i18n.js` updates explicitly marked interface labels in place. It does not
  remount forms, replace calendar cells, reload the page, close dialogs, or reset
  active filters, the selected day, theme, journal expansion, or chart instances.
- `messages.js` contains bilingual display copy. Date-only records are formatted
  as UTC civil dates so a language change cannot move the selected day.
- Trading symbols, IDs, original notes, saved journal values, and custom/default
  AI prompt templates retain their original contents. Translated select labels
  retain their existing Chinese `value` identifiers for storage and AI requests.
- Chart display labels and tooltips change without recalculating the underlying
  dataset. Imported FIFO realized P&L, matching/merge logic, R2 requests, AI request
  payloads, schemas, storage keys, and the six themes keep their existing contracts.
- Service-provided error text is preserved; interface error/status wrappers and
  application-owned errors are localized. Browser-owned file-picker/date-input
  chrome follows the browser/OS language.
- There is no new locale-dependent monetary conversion or financial calculation.

## Develop and verify

This is a static ES-module application. Serve the repository over HTTP, for
example `python3 -m http.server 8080`, then open its URL in a browser. No build or
package installation is required.

```sh
npm run check                # JavaScript syntax
npm test                     # Existing baseline comparison + native i18n contracts
npm run test:i18n:timezones   # 23 i18n contracts in UTC, Los Angeles and Shanghai
npm run test:timezones        # 52 existing data/UI contracts in all three zones
npm run test:strict           # Also fails on unchanged legacy data defects
```

At this change's validation checkpoint, all 23 localization contracts passed in
each timezone. Existing contracts still met 46/52 expectations in UTC and
Shanghai, and 43/52 in Los Angeles. The other 6/9 failures reproduce against the
pinned legacy baseline and are documented in `tests/README.md`; they are not
passing tests or part of this localization fix. Strict mode remains nonzero.

The additional checks cover locale persistence/fallback, actual switch events,
all tabs/themes, explicit catalog completeness, date labels, mobile/desktop DOM
structure, unsaved daily/weekly/AI/R2/import fields, immutable select values,
modal close/reopen, in-flight AI status, byte-identical AI requests, chart instance
and numeric-data stability, error/empty/loading copy, and untranslated user text.

Tests use synthetic DOM/chart/network doubles. They do not certify screenshot
layout, native browser behavior, real broker imports, R2/AI connectivity, or
production deployment. Those require separate browser/integration verification.

## Adding interface copy

Add both `zh-CN` and `en` entries to the catalog, then use `data-i18n` for static
text or `setMessage` / `messageHTML` for runtime labels. Pass runtime values as
parameters, never concatenate user text into a translation key. Attribute labels
use `data-i18n-placeholder`, `data-i18n-title`, or `data-i18n-aria-label`.

Do not mark editable input/textarea values for translation. `data-i18n-readonly`
is restricted to the calculated weekly Yes/No display. Use escaped text when
rendering user content in HTML so it cannot become interface translation markup.

## Deployment cache consistency

Local scripts, their ES-module dependencies and styles use the same deployment
version query. Update that revision together when releasing interface changes.
This prevents a normal page refresh from combining new HTML with previously
cached JavaScript or CSS. External vendor resources and API requests are unchanged.
